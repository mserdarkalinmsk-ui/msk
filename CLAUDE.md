# Portfolio Ledger — working principles

Read this before any change. It applies to every session and every agent working in this repository.

## What this is

Portfolio Ledger is a single-file HTML app that a programme office uses to follow donor-funded projects: budgets,
financial reports, staff, forecasts, alerts, monthly packs and presentations. Source: `next/` (Vite + Preact + TypeScript).
The delivered file is `portfolio-ledger-next.html` at the repository root (a copy of `next/dist/index.html`).

The person using it is a finance and programme manager, not a developer. They speak Turkish; replies to them are in
Turkish, short and concrete. Code, comments, commit messages and the app's own text stay in English.

## Non-negotiable rules

1. **No invented data, ever.** No sample projects, demo figures, placeholder notes or "realistic" names in the app or
   in anything shown to the user. If data is missing, the app says so; it never fills the gap.
2. **No real data in git.** Real project names, people, suppliers and amounts never go into the repository, test
   fixtures or commit messages. Tests use neutral placeholders (Alpha/Beta… surnames, One/Two… given names, codes
   like `lang`, `tsk`). Real data lives only in the user's browser and backups.
3. **No AI in the app and no AI traces in outputs.** No "generated by", no assistant wording in exports, letters or
   slides. No model names in commits or code.
4. **Amounts show two decimals** in tables and exports (charts and headline tiles may abbreviate: €1.6M).
5. **Payments and purchase orders stay on their own budget line**; nothing is silently moved between lines.
6. **No bubble charts, no 3D charts.** Charts follow the one chart language in `src/ui/Chart.tsx` (`polish`).
7. **Deleting anything needs the admin password** (as the app already does); never weaken that.
8. **No new npm packages.** Use what is in `package.json`.

## Quality gates — a change is finished only when all pass

Run from `next/`:

```bash
npx tsc --noEmit -p .
timeout 250 npx vitest run          # every test passes
npm run build && cp dist/index.html ../portfolio-ledger-next.html
timeout 560 node tests/e2e.mjs      # must end with "All checks passed"
```

Never skip, disable or weaken a test to get green. A bug that is fixed gets a test that would have caught it.

Playwright in this environment: `import { chromium } from 'playwright-core'`, launch with
`executablePath: '/opt/pw-browsers/chromium'`, and add an init script setting `localStorage 'pl-digest-seen' = 'off'`.
Scratch scripts go in `next/zz-*` (git-ignored) and are deleted before committing.

## How agents work here

Work in rounds. One round = **find → verify → fix → guard → report**.

1. **Find.** Each agent owns one area and reads only what it needs:
   - *Figures*: `src/domain/` (calc, forecast, analysis, monitor). Formulas, rounding, divide-by-zero, date edges,
     totals that must agree across screens.
   - *Screens*: every page at 1280, 1440 and 1920 px, light and dark. Overflow, overlapping text, cut labels,
     horizontal scroll, misaligned columns.
   - *Outputs*: slides (`Deck`, `Story`), PDF printing, PowerPoint, Excel, Word letters. Content past the slide
     footer, broken characters, empty sections, wrong totals.
   - *Import*: report, Word and PDF readers (`documents.ts`, `ReportImport`, `applydocs`). Lines split or merged
     wrongly, missed fields, symbol-font bullets.
   - *Robustness*: backup, encryption, shared copies, malformed input. Crashes, data loss, leaks.
2. **Verify.** Every finding is reproduced before anything is changed: a failing test, a screenshot, or a measured
   number. A finding that cannot be reproduced is dropped, not "fixed just in case".
3. **Fix.** Smallest change that removes the cause, one topic per commit. Follow the existing style of the file.
   Do not redesign, rename or reformat code that the finding does not touch.
4. **Guard.** Turn the class of bug into an automatic check (a unit test, or a check in `tests/e2e.mjs`) so it cannot
   come back silently.
5. **Report.** Pass all gates, commit, push to the session's own branch, and write a short report in Turkish:
   what was found, what was fixed, what was left and why. Never claim a check that was not run.

### Limits for unattended runs

- Do not change visual direction, colours, wording the user chose, or app behaviour the user asked for. Those are
  the user's decisions: list them as proposals in the report instead.
- Do not delete data, features or tests.
- At most 10 fixes per round; stop earlier when the remaining findings are low value.
- No pull requests and no pushes to other branches unless the user asks.
- If the gates cannot be made to pass, push nothing and report the blocker.

## Delivery (interactive sessions with the user)

After the gates: commit and push (commit and push as separate commands), publish the app page, give the download
link to `portfolio-ledger-next.html` on the working branch, and send the real-data copy only when it exists in that
session (it is never committed).
